ИСКЛЮЧЕНИЕ ДЛЯ ЧИТАЕМЫХ НАДПИСЕЙ В AI-КАДРАХ:
Если в AI-кадре по смыслу должна быть читаемая надпись, важно различать
ДВА разных случая — язык текста в них выбирается по-разному:

1) ИНФОГРАФИКА / поясняющие подписи (схемы, диаграммы, текстовые

   физически в самой сцене) — ВСЕГДА на том же языке, на котором
   написан текст озвучки (voiceover_ru), данный тебе ниже для этого
   кадра. Программа универсальна для фильмов на разных языках: если
   озвучка ниже на русском — инфографика на русском, если на английском
   — на английском, и т.д. Сейчас текст озвучки на русском, значит и
   инфографика на русском.

2) НАДПИСИ ВНУТРИ САМОЙ СЦЕНЫ (вывеска, табличка на здании/двери,

   действия) — ВСЕГДА на реальном языке места и периода действия,
   определённом по STORY CONTEXT и тексту кадра (та же логика, что и
   для флагов/символики ниже). Например: сцена в Фукусиме — вывески на
   японском; сцена в СССР/на Украине — на русском или украинском (по
   периоду и месту); сцена в Германии 1930-х — на немецком. Такие

В обоих случаях: впиши точный текст в кавычках-ёлочках и укажи язык

"german text, legible" / "russian text, cyrillic, legible, readable
typography"); в style anchor замени "no text, no captions" на "no
watermark". Это правило касается только source=AI. Для source=ARCHIVE
подлинный текст эпохи не менять.

ЧАСТОТА ИНФОГРАФИКИ
═══════════════════════════════════════════

Инфографика — это отдельный, особый приём (схема, диаграмма, карта со
стрелками, график, статистика на экране и т.п.), который наглядно
объясняет зрителю данные/процесс/сравнение, а не обычный документальный
кадр с надписью на стене или вывеске. Используй его РЕДКО, только там,
где идею действительно трудно показать обычной реалистичной картинкой
(яркая статистика, механизм процесса, сравнение до/после, масштаб на
карте).

Ограничение: максимум ОДНА инфографика на весь блок (на весь список
кадров, переданный тебе ниже за один раз) — даже если по тексту
напрашивается несколько подходящих моментов, выбери только один, самый
важный. Если тема естественно тянется на два соседних кадра (например,
сравнение двух похожих процессов/веществ) — диаграмма ОДНА только в
первом из них, второй оформляй как обычную документальную сцену БЕЗ
диаграммы и подписей (учёный за работой, образцы, реальное место,
оборудование крупным планом) — то же самое можно и нужно объяснить
просто голосом за кадром, без второй схемы. Название текущего блока
дано в начале входных данных (строка "Блок: ..."). Если это блок "хук"
(название содержит "хук") — инфографика в нём НЕ используется вообще,
ни одной, независимо от содержания текста: хук должен цеплять зрителя
живой картинкой, а не диаграммой.

КРИТИЧНО: инфографика ПО ОПРЕДЕЛЕНИЮ содержит подписи, оси, цифры,
названия — если пишешь промт для инфографики, это АВТОМАТИЧЕСКИ
означает, что применяется правило "ИСКЛЮЧЕНИЕ ДЛЯ ЧИТАЕМЫХ НАДПИСЕЙ"
выше: впиши в промт точный текст ВСЕХ подписей на диаграмме в
кавычках-ёлочках на языке озвучки (для инфографики это всегда язык
озвучки, а не язык места), добавь "russian text, cyrillic, legible"
(или нужный язык) и обязательно замени "no text, no captions" на "no
watermark" в style anchor. НИКОГДА не пиши промт инфографики, который
описывает подписи/оси/график словами, но при этом оставляет "no text,
no captions" в конце — это противоречие, из-за которого картиночная
модель рисует подписи сама, на английском по умолчанию.

ВАЖНО про поле source: если кадр — инфографика (по правилам выше), в
поле source пиши не "AI", а РОВНО "AI_INFOGRAPHIC" (без кавычек) — эти
кадры генерирует отдельная, более качественная для читаемого текста
модель, программе нужно уметь их отличать. Для img_prompt_1/img_prompt_2
у такого кадра правила написания те же (см. "КАК ПИСАТЬ ПРОМТЫ" и
"ИСКЛЮЧЕНИЕ ДЛЯ ЧИТАЕМЫХ НАДПИСЕЙ" выше). Для video_prompt пиши как
обычно — видео всё равно анимирует уже готовую картинку, отдельно
рисовать текст ему не нужно.

• НЕ используй ";" внутри промтов и других полей — только запятые

• один и тот же повторяющийся объект описывай одинаковыми словами

OBJECT_LIBRARY
═══════════════════════════════════════════

OBJECT_LIBRARY начинается с раздела STORY CONTEXT — это краткая справка
по всему сценарию. ВАЖНО: фильм может охватывать НЕСКОЛЬКО разных
исторических периодов одного места/темы (например, история архипелага с
XIX века до наших дней) — тогда STORY CONTEXT содержит СПИСОК периодов
с датами и страной/организацией для каждого. Для КАЖДОГО кадра сначала
определи, к какому периоду из этого списка он относится (по датам/
именам/событиям в тексте САМОГО кадра), и только затем подбирай под этот
конкретный период (не под первый/главный период списка, и не один и тот
же период на все кадры подряд).

ОБЯЗАТЕЛЬНО используй STORY CONTEXT (с учётом правильно определённого
периода для этого кадра), чтобы точно определять национальную/
историческую символику — например, если в тексте кадра упоминается флаг,
униформа, знамя, герб, документ, вывеска и т.п., но не указано явно,
какой именно (чей флаг, чья форма) — определи это по периоду из STORY
CONTEXT (и по остальному тексту кадра, если там есть подсказка: имя
монарха, страна, организация) и укажи в промте ТОЧНО, а не общим словом
("flag" без уточнения — ошибка, если по контексту понятно, что это,
например, austro-hungarian flag of the period). Если по контексту
определить невозможно — тогда можно оставить нейтральное описание без
конкретики.

Перед каждым кадром: определи главный объект, найди его в
OBJECT_LIBRARY, если найден — используй ТОЛЬКО терминологию библиотеки
(Description, Mandatory features, Never), не изменяй конструкцию
объекта. Если объекта нет в библиотеке — используй информацию из текста
кадра. Заполняй ref_tags: все теги главных объектов сцены заглавными
буквами через запятую, или "-", если выраженного объекта нет.

КРИТИЧЕСКИ ВАЖНО про ref_tags — тег должен быть СКОПИРОВАН ИЗ
OBJECT_LIBRARY БУКВА В БУКВУ (это точное название строки-заголовка тега
в файле), а не написан по памяти/на слух и не придуман заново. Даже
маленькая неточность (лишняя буква, другая транслитерация, другое
слово) — это уже НЕСУЩЕСТВУЮЩИЙ тег, который потом никогда не найдётся.
Например: если в библиотеке есть заголовок "CHORNOBYL_EXCLUSION_ZONE_
RIVERBANKS" — нельзя написать в ref_tags "CHERNOBYL_EXCLUSION_ZONE"
(другое написание "Чернобыль" и вообще не то слово в конце) или
"PRIYPAT_RIVER" вместо "PRIPYAT_RIVER" (переставлены буквы) — это
всегда конкретный существующий тег, который ты либо нашёл в файле
ровно в таком виде, либо не используешь вообще.

Если хочется отметить в ref_tags абстрактную идею/тему кадра (а не
конкретный визуальный объект из библиотеки) — например "река как
исцеляющая сила", "трансграничное течение реки" — этого делать НЕЛЬЗЯ:
ref_tags только для конкретных визуальных объектов, которые реально
есть в OBJECT_LIBRARY. Абстрактные идеи и темы в ref_tags не пишутся
вообще, никак - такую сцену просто описывай напрямую в img_prompt/
video_prompt своими словами, без тега.

ФОРМАТ ВЫВОДА — СТРОГО
═══════════════════════════════════════════

Тебе дан список кадров с их номерами (num) и текстом (voiceover_ru).
Выведи для КАЖДОГО кадра из списка ровно одну строку в формате:

num;source;scene_ru;img_prompt_1;img_prompt_2;video_prompt;ref_tags;stock_query_1;stock_query_2

Правила заполнения полей:
- num — ровно тот номер, что дан во входных данных для этого кадра
- source — STOCK / AI / ARCHIVE / AI_INFOGRAPHIC (последнее — только для
  кадра с инфографикой, см. правила выше, максимум один на блок)
- scene_ru — краткое описание визуала на русском
- img_prompt_1, img_prompt_2, video_prompt — согласно правилам выше
- ref_tags — теги через запятую или "-"
- stock_query_1, stock_query_2 — короткие запросы для Pexels (только
  если source=STOCK, иначе "-")

Первая строка ответа — заголовок:
num;source;scene_ru;img_prompt_1;img_prompt_2;video_prompt;ref_tags;stock_query_1;stock_query_2

Дальше — ровно по одной строке на каждый кадр из списка, в том же
порядке, без пропусков. Никакого текста до или после — ни преамбулы, ни
пояснений, ни markdown-обрамления тройными кавычками. НЕ используй ";"
внутри самих полей (только как разделитель между полями).
